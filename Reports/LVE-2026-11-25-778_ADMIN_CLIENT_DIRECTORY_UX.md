## 5. تصميم الحل والتنفيذ في countflow-admin.html

### 5.2 البحث الذكي

يركّب البحث طلبات خادمية على خصائص العميل الموجودة:

- الاسم.
- كود العميل.
- النشاط.
- مسؤول التواصل.
- بريد التواصل.
- الهاتف.

كما يبحث عن مدير العميل عبر display_name وusername في count_client_members، ويحوّل نتائج مطابقة المدير إلى نطاق client_id ثم يدمجها مع نتائج العملاء.

تم تنظيف أحرف PostgREST الخاصة في عبارة البحث، وتحديد طول النص قبل بناء مرشحات البحث.

**حد معروف:** استعلام اكتشاف المديرين المطابقين محدود بـ1,000 سجل في الطلب الواحد. لا يمثل هذا حداً لقائمة العملاء ذاتها، لأن قائمة العملاء تستخدم Pagination خادمياً. ينبغي تحويل اكتشاف المديرين إلى مسار بحث خادمي أوسع إذا تجاوز عدد عضويات المديرين هذا الحجم.

### 5.3 الفرز والترقيم

- حجم الصفحة: 25 عميلاً.
- طلب البيانات باستخدام range من الخادم.
- count exact لتحديد إجمالي النتائج والصفحات.
- الفرز حسب created_at أو code أو name أو industry أو status.

- إعادة الصفحة إلى الأولى عند تغيير البحث أو الحالة أو معيار الفرز.

تم إلغاء الاعتماد على limit(300) في تحميل قائمة العملاء المستخدمة في النظام الأم، واستبداله بتحميل صفحات 500 عند إنشاء اختيارات العميل المرتبطة بالتكليف ودليل الأصناف. أما دليل العملاء نفسه فيستخدم 25 سجلاً للصفحة.

### 5.4 Modal إنشاء/تحرير العميل

النموذج يستخدم الحقول الفعلية في count_clients:

- code
- name
- industry
- contact_name
- contact_email
- contact_phone
- default_timezone
- default_currency
- status

التحقق:

- الكود: أحرف كبيرة وأرقام وشرطة سفلية/عادية، من 2 إلى 40.
- الاسم: من حرفين إلى 160 حرفاً.
- البريد: تحقق HTML من النوع email.
- الهاتف: حقل tel بحد أقصى 40.
- العملة: واحدة من الخيارات الحالية في الواجهة EGP / SAR / AED / USD.
- المنطقة الزمنية: القاهرة / الرياض / دبي / UTC.

**قيد هوية السجل:** كود العميل يصبح للقراءة فقط بعد الإنشاء؛ لا يسمح بتغيير مفتاح التعريف داخل نموذج التحرير.

**تحديث آمن:** التعديل يقتصر على خصائص العميل وstatus، ويستخدم المعرف المحدد. لا ينفذ حذفاً ولا يغيّر client_id في المشاريع أو العضويات أو الكتالوج.

### 5.5 إدارة مديري العميل

إدارة المديرين مرتبطة بالعميل الذي فتحه المستخدم، ويجري تصفية المديرين باستخدام client_id نفسه، مع قصر الدور المعروض على client_admin ضمن scope=client.

تتضمن الإجراءات:

1. إنشاء حساب مدير جديد أو ربط حساب Auth موجود.
2. تعديل display_name وusername مع تقييد التحديث بمعرف العضوية ومعرف العميل معاً.
3. إيقاف العضوية بتغيير status إلى paused.
4. إعادة التفعيل بتغيير status إلى active.
5. إعادة تعيين كلمة المرور عبر Edge Function الحالية وباستخدام member_type=client وclient_id وmember_id.

لم يُضف زر حذف مادي. الإيقاف لا يحذف هوية Auth ولا سجل العضوية.

## 9. حدود الاختبار والمخاطر المتبقية

### ما لم يتم اختباره

1. فتح تبويب العملاء داخل جلسة مالك مصادق عليها والنقر الفعلي على جميع عناصر الواجهة.
2. تجربة Modal إنشاء عميل على بيانات اختبار مصرح بها.
3. تعديل عميل موجود والتحقق المرئي من انعكاس البيانات على التبويبات الأخرى.
4. دخول مدير عميل بحساب فعلي والتحقق من حدود الوصول عبر الواجهة وطلبات API.
5. تجربة إيقاف/إعادة تفعيل مدير عميل على حساب QA معتمد.
6. إعادة تعيين كلمة مرور حساب QA حقيقي.
7. اختبار عرض الدليل على هاتف فعلي بعد المصادقة.
8. اختبار البحث عن المديرين عند تجاوز 1,000 عضوية مطابقة.

### سجل المعرفة الناقصة

- لا يوجد عقد عام في count_client_members لعرض البريد الحقيقي المرتبط بـAuth؛ النموذج يعرض الاسم واسم المستخدم. يلزم قرار منفصل وعقد Edge قراءة مصادق عليه قبل إظهار البريد.
- لا توجد بيانات عميل أو عضوية عميل حالية في المشروع وقت الرصد، ولم يتم إنشاء سجلات تجريبية بسبب حدود حماية البيانات.
- اختبار CI العام لا يثبت تجربة Admin بعد المصادقة.
- لا يوجد دليل على اختبار ضغط لدليل بعشرات آلاف العملاء أو آلاف المديرين.
- صلاحية مالك المنصة تعتمد على آلية التعرف الحالية على بريد المالك المؤكد؛ لم تُغيّر هذه المهمة نموذج هوية المالك.
- نجاح الاستدعاء البرمجي لا يثبت أن كل تصميم التفاعلات مقبول بصرياً لدى المالك.

### المخاطر التي تم تجنبها

- عدم إدخال بريد Auth إلى جدول العميل أو جدول العضوية دون عقد واضح.
- عدم السماح بتغيير كود العميل بعد الإنشاء.
- عدم حذف العميل أو العضوية مادياً.
- عدم توسيع صلاحيات Client Admin إلى إدارة المنصة.
- عدم تحويل العميل أو مديره إلى عضوية مشروع أو دور project عن طريق الخطأ.
- عدم إنشاء migration جديدة لتكرار نموذج موجود.
- عدم اختبار الكتابة على دفعة QA أو مشروع حقيقي.
